# 6 Metodología — TANISH E-Commerce

## Enfoque

El proyecto utiliza un **enfoque híbrido de gestión** con desarrollo iterativo organizado en sprints. Combina una fase inicial de planificación predictiva con ciclos iterativos de configuración, validación y corrección de brechas.

## Componente Predictivo

| Elemento | Descripción |
|---|---|
| Alcance | Definido en la auditoría de alineación y matriz de trazabilidad |
| EDT | Estructura de descomposición del trabajo (5.9) |
| Riesgos | Matriz de gestión de riesgos (5.10) |
| Interesados | Registro de interesados (5.11) |
| Presupuesto | Estimación de costos (5.12) |
| Documentación académica | Secciones del informe final |

## Componente Iterativo

| Elemento | Descripción |
|---|---|
| Desarrollo incremental | Cada sprint aborda un grupo de requisitos |
| Sprints | Ciclos de trabajo con objetivo específico |
| Validación | Verificación de funcionalidad en cada sprint |
| Pruebas | Unitarias, smoke y UAT |
| Corrección de brechas | Ajustes basados en evidencia |

## Prácticas Inspiradas en Agile/Scrum

| Práctica | Aplicación |
|---|---|
| Sprints académicos | Ciclos de trabajo organizados |
| Definition of Done | Criterios de aceptación por requisito |
| Tablero kanban | Seguimiento de estado de requisitos |
| Trazabilidad | Matriz de requisitos ↔ sprints |
| Evidencia verificable | Cada resultado respaldado por código/runtime |

## Sprints

| Sprint | Nombre | Objetivo |
|---|---|---|
| 00 | Baseline | Documentar estado actual |
| 01 | B2C Commerce | Restaurar carrito + checkout |
| 02 | Roles + Inventario | MFA, roles, movimientos demo |
| 03 | Analytics | GA4 + eventos |
| 04 | Security | MFA + backups + HTTPS |
| 05 | Testing | Unit + smoke + UAT |
| 06 | Academic | Documentos académicos |

## Roles

| Rol | Responsabilidad |
